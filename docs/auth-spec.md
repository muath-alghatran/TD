# Trust Drive — نظام الحساب والدخول
### مواصفة للمبرمج · المرحلة الأولى

## 1. تقييم الفكرة الأصلية

| القرار | الحكم |
|---|---|
| البدء بصفة زائر | ✅ **صحيح تماماً** — إجبار التسجيل قبل رؤية القيمة يفقدك أغلب الزوار |
| رقم الجوال كهوية | ✅ **صحيح** — أنسب من الإيميل في السوق السعودي |
| واتساب كقناة | ✅ **ذكي** — وفيه فرصة أكبر مما قصدت (انظر القسم ٦) |
| «كراجي» باهتاً مع ملاحظة | ✅ فكرة جيدة، وتحتاج صياغة أدق (القسم ٣) |
| **كود من ٤ أرقام** | ❌ **ضعيف أمنياً — غيّره إلى ٦** |
| **الاسم الثلاثي عند التسجيل** | ⚠️ **أخّره** — يقتل التحويل بلا مقابل |
| **واتساب كقناة وحيدة** | ❌ **خطر تشغيلي** — لا بد من بديل |

## 2. التصحيحات الثلاثة

### ٢.١ · الكود: ٦ أرقام لا ٤

أربعة أرقام = ١٠٠٠٠ احتمال فقط. مهاجم آلي يجرّبها كلها في دقائق، وأي تحديد للمحاولات يصبح هو خط الدفاع الوحيد — وهذا هشّ. ستة أرقام = مليون احتمال، وهي المعيار الذي يستخدمه كل مزوّد جاد.

**الفرق في تجربة المستخدم: صفر.** الفرق في الأمان: مئة ضعف. لا يوجد سبب واحد للإبقاء على أربعة.

**السياسة الكاملة:**

| البند | القيمة |
|---|---|
| طول الكود | ٦ أرقام عشوائية |
| الصلاحية | ٥ دقائق |
| محاولات الإدخال | ٥ ثم قفل ١٥ دقيقة |
| إعادة الإرسال | بعد ٦٠ ثانية · ٣ مرات كحد أقصى في الساعة |
| حد الطلبات لكل رقم | ٥ في الساعة |
| حد الطلبات لكل IP | ٢٠ في الساعة |
| التخزين | **مُجزّأ (hashed) في قاعدة البيانات، لا نصاً صريحاً** |
| بعد الاستخدام | يُبطَل فوراً — لا يُقبل مرتين |

**قاعدة أمنية مهمة:** لا تكشف أبداً إن كان الرقم مسجّلاً أم لا. الرسالة واحدة دائماً: «أرسلنا الكود». وإلا صار الموقع أداة لمعرفة من هم عملاؤك.

### ٢.٢ · الاسم: أخّره إلى ما بعد الطلب الأول

طلب الاسم الثلاثي في شاشة التسجيل يضيف احتكاكاً في اللحظة الأكثر هشاشة — قبل أن يحصل العميل على أي قيمة.

**متى تحتاج الاسم فعلاً؟** عند أول طلب — لبوليصة الشحن أو استلام الفاتورة. **إذاً اطلبه هناك**، حيث يكون العميل قد قرر الشراء ولن يتراجع بسبب حقل نصي.

النتيجة: التسجيل يصبح **خطوتين فقط** — رقم، ثم كود. لا شيء غيرهما.

> راجع مع محاسبك متطلبات ZATCA لبيانات المشتري في فواتير الأفراد — قد تختلف عن فواتير المنشآت.

### ٢.٣ · واتساب يحتاج بديلاً — دائماً

واتساب قد يفشل لأسباب خارجة عن يدك: الرقم غير مسجل في واتساب، التطبيق غير مثبّت، قالب الرسالة معلّق، أو انقطاع في الخدمة. وأي واحد منها يعني **عميل لا يستطيع الدخول إلى حسابه** — وهو أسوأ فشل ممكن.

**السياسة:**
1. الافتراضي: واتساب
2. لم يصل خلال ٣٠ ثانية → يظهر زر **«أرسله برسالة نصية بدلاً منه»**
3. فشل واتساب تقنياً → تحويل تلقائي إلى SMS دون أن يشعر العميل
4. لوحة التحكم تعرض نسبة نجاح كل قناة يومياً

> تحقق من متطلبات قوالب المصادقة في WhatsApp Business API واعتمادها **قبل** بناء النظام، لأن الموافقة تستغرق وقتاً وقد تتغير شروطها.

## 3. الفرصة الكبيرة: الحساب يُخلق من الطلب

هذه أهم فكرة في المستند.

في تصورك الحالي هناك مسار «إنشاء حساب» منفصل. **احذفه.**

> **لا تجعل التسجيل خطوة يختارها العميل — اجعله نتيجة طبيعية لأول طلب.**

العميل يتصفّح كزائر، يختار قطعة، يصل للدفع — وهناك نطلب رقم جواله **لتأكيد الطلب** (وهو أمر يتوقعه ويفهمه تماماً)، ونرسل الكود. بمجرد إدخاله يكون قد **صار عميلاً مسجّلاً دون أن يمرّ بشاشة تسجيل واحدة**.

الفرق نفسي بحت لكنه حاسم: «سجّل حساباً» تبدو التزاماً على العميل، بينما «أكّد رقمك لنرسل لك حالة الطلب» تبدو خدمة له. النتيجة واحدة، والفارق في التحويل كبير.

### شرط لا يقبل التهاون: **لا تفقد عمل الزائر أبداً**

الزائر قبل الدخول:
- سيارته المؤكدة من الاستمارة → تُحفظ محلياً في المتصفح
- سلته
- طلبات «أبلغني عند التوفر»

**عند الدخول، كل هذا يُنقل إلى حسابه تلقائياً وبصمت.** إن جعلته يعيد تصوير الاستمارة بعد الدخول، فقد أهدرت أفضل ما في منتجك.

**قواعد الدمج:** نفس رقم الهيكل موجود مسبقاً → لا تكرر · موجود عند حساب آخر → أضفه لهذا الحساب أيضاً (السيارة تُباع وتُشترى) · تعارض في الفئة → اعتمد المؤكد يدوياً.

## 4. متى نطلب الدخول — وكيف

**القاعدة:** لا نطلب الدخول لعرض شيء. نطلبه فقط لـ**حفظ** شيء أو **تتبّعه**.

| الفعل | زائر | مسجّل |
|---|---|---|
| تصوير الاستمارة وتأكيد السيارة | ✅ | ✅ |
| تصفّح المخططات والأسعار والوعد | ✅ | ✅ |
| إضافة للسلة | ✅ | ✅ |
| **حفظ سيارة ثانية في كراجي** | 🔒 | ✅ |
| **إتمام الطلب** | 🔒 | ✅ |
| **أبلغني عند التوفر** | 🔒 | ✅ |
| تتبّع الطلبات والضمانات | 🔒 | ✅ |

### صياغة «كراجي» للزائر

فكرتك بجعله باهتاً صحيحة، لكن **لا تجعله باهتاً وفارغاً** — اجعله باهتاً و**فيه سيارته التي أدخلها فعلاً**، مع سطر واحد:

> **كراجي**
> `تويوتا كامري ٢٠٢١ — محفوظة مؤقتاً على هذا الجهاز`
> **أكّد رقمك لتحتفظ بها** ← زر

الفرق جوهري: العميل لا يرى ميزة مقفلة يُطلب منه الدفع لفتحها — بل يرى **شيئاً يملكه بالفعل ومعرّضاً للضياع**. الدافع للحفظ أقوى بكثير من الدافع للحصول.

**قاعدة صارمة:** كل شاشة دخول تبدأ من فعل — «أكّد رقمك لتتبّع طلبك»، «أكّد رقمك لنبلغك عند التوفر». لا تعرض شاشة دخول بلا سبب ظاهر أمامها.

## 5. البقاء داخل الحساب

هذه نقطة تُغفل كثيراً وتكلف غالياً: **إن طلبت كوداً في كل زيارة، فقدت العملاء المتكررين.**

- جلسة صالحة **٩٠ يوماً** مع تجديد صامت عند كل استخدام
- الخروج يدوي فقط، أو عند تغيير الرقم
- «الأجهزة النشطة» في الحساب مع إمكانية إنهاء أي جلسة

الهدف: العميل يدخل مرة واحدة كل ثلاثة أشهر. أي أكثر من ذلك يعني أنك تعاقبه على الوفاء.

## 6. الفرصة التي فوّتّها: واتساب ليس قناة كود

أنت تستخدم واتساب لإرسال رقم عشوائي ثم تنساه. **هذا إهدار لأثمن ما في الفكرة.**

رسالة الكود هي أول محادثة بينك وبين العميل على واتساب — وهي **قناة مفتوحة موافَق عليها ضمنياً**. اجعلها مسار كل شيء بعدها:

```
كود الدخول
    ↓  (نفس المحادثة)
تأكيد الطلب ورقمه
    ↓
«وصلت قطعتك إلى مستودعنا»
    ↓
رابط تتبّع الشحنة
    ↓
«توفرت القطعة التي طلبت إبلاغك عنها»
    ↓
تذكير الصيانة الدورية بعد ٦ أشهر
```

المنافس يرسل إيميلاً لا يُقرأ. أنت تملك **خيطاً واحداً متصلاً** يجد فيه العميل تاريخ تعامله كله. هذه ميزة احتفاظ حقيقية لا تكلفك شيئاً إضافياً — فقط قرار تصميم.

> اطلب موافقة صريحة على الرسائل التسويقية (تذكير الصيانة) بشكل منفصل عن الرسائل التشغيلية، مع خيار إيقاف واضح. راجع أنظمة مكافحة الرسائل غير المرغوبة مع مستشار نظامي.

## 7. حالات لا تنسها

| الحالة | التصرف |
|---|---|
| الكود انتهت صلاحيته | «انتهت صلاحية الكود» + زر إرسال جديد — لا تعيده لشاشة الرقم |
| ٥ محاولات خاطئة | قفل ١٥ دقيقة + رسالة تنبيه على واتساب |
| رقم بصيغة خاطئة | تحقق فوري أثناء الكتابة، لا بعد الإرسال |
| أراد تغيير الرقم | رابط «تعديل الرقم» ظاهر في شاشة الكود |
| **رقم أُعيد تخصيصه لشخص آخر** | خمول ١٢ شهراً + دخول جديد ← أنشئ ملفاً جديداً ولا تكشف بيانات السابق. **مهم — الأرقام تُعاد فعلاً** |
| فقد الوصول للرقم نهائياً | مسار استرجاع يدوي عبر خدمة العملاء بتحقق من آخر طلب |
| زائر بسيارة ثم دخل بحساب فيه سيارات | ادمج ولا تستبدل |

## 8. الواجهة

طبّق نفس نظام التصميم — لوح ورقي، علامات تسجيل، والانضباط اللوني نفسه.

**شاشة الرقم:** حقل واحد بمقدمة `+966` ثابتة · لوحة أرقام على الجوال · تنسيق تلقائي · زر واحد.

**شاشة الكود:** ست خانات منفصلة بخط `IBM Plex Mono` (نفس خط أرقام القطع — اتساق مقصود) · انتقال تلقائي بين الخانات · **دعم اللصق الكامل للكود دفعة واحدة** · `autocomplete="one-time-code"` للتعبئة التلقائية · عدّاد إعادة الإرسال · رابط تعديل الرقم.

**اللون:** الأخضر والأصفر محجوزان لحالة التوفر ولا يُستخدمان هنا. حالة الخطأ بالحبر والنص، لا بلون جديد.

**الوصولية:** الخانات الست مجموعة واحدة بـ`aria-label` واضح · إعلان الأخطاء عبر `aria-live` · تنقل كامل بالكيبورد.

## 9. نموذج البيانات

```
User          id · phone (فريد، بصيغة E.164) · fullName (اختياري)
              · createdAt · lastLoginAt · status

OtpRequest    id · phoneHash · codeHash · channel (whatsapp|sms)
              · expiresAt · attempts · consumedAt · ip · userAgent

Session       id · userId · refreshTokenHash · deviceLabel
              · lastSeenAt · expiresAt · revokedAt

Vehicle       ... · userId (nullable) · guestToken (nullable)
```

**قواعد إلزامية:**
- الرقم والكود **مُجزّآن (hashed)** — لا يُخزَّن أي منهما نصاً صريحاً
- كل الأرقام بصيغة E.164 (`+9665XXXXXXXX`) قبل الحفظ والمقارنة
- التحقق من الكود **في الخادم فقط** — لا يصل الكود إلى المتصفح أبداً
- سجل كل محاولة دخول (نجاح وفشل) مع IP للمراجعة الأمنية
- احذف سجلات OTP المنتهية بعد ٢٤ ساعة

## 10. معايير القبول

- [ ] الزائر يكمل: استمارة ← سيارة ← مخطط ← قطعة ← سلة — **بلا تسجيل**
- [ ] بعد الدخول: سيارته وسلته وتنبيهاته انتقلت كاملة بلا فقد
- [ ] الكود ٦ أرقام · ٥ دقائق · ٥ محاولات · تجزئة في القاعدة
- [ ] فشل واتساب → تحويل تلقائي إلى SMS
- [ ] زر «أرسله برسالة نصية» يظهر بعد ٣٠ ثانية
- [ ] الرسالة واحدة سواء كان الرقم مسجلاً أم لا
- [ ] لصق الكود دفعة واحدة يعمل · التعبئة التلقائية تعمل
- [ ] الجلسة تصمد ٩٠ يوماً
- [ ] الاسم يُطلب عند أول طلب لا عند التسجيل
- [ ] لا لون مشبع في شاشات الدخول

## الخلاصة

فكرتك سليمة الأساس. التغييرات الأربعة:

1. **٦ أرقام لا ٤** — بلا نقاش
2. **بديل SMS إلزامي** — واتساب وحده خطر تشغيلي
3. **الاسم بعد الطلب لا قبله**
4. **احذف مسار «إنشاء حساب»** — اجعل الحساب نتيجة أول طلب

والفرصة: **اجعل واتساب خيط العلاقة كلها، لا قناة كود عابرة.**
